# Само през Tor (П6, експеримент)

Без TURN контактът вижда IP адреса ви: това е присъщо на P2P. Режимът „Само през Tor“ го скрива. Двамата
се свързват само през две onion услуги, както при Briar и Cwtch. Цената: няма WebRTC (без разговори), а
свързването е бавно (до няколко минути).

## Къде работи

| | |
|---|---|
| Настолно (Tauri) | Билд с `cargo build --features tor-transport` (`src-tauri/src/tor_net.rs`). |
| Android | APK от workflow-а **Android APK with Tor (experiment)** (`.github/workflows/android-tor.yml`). Той билдва `android-tor/` (същият `tor_net.rs`) с NDK-то на runner-а като `libp2ptor.so`, само за arm64-v8a, debug подпис. В обикновения APK библиотеката я няма и настройката не се показва. |
| Браузър (PWA) | Не. Браузърът не може да пуска Tor в себе си. |

## Как работи

1. При включен режим приложението стартира Arti и onion услуга с нов адрес при всяко пускане.
2. Поканата носи `a=x-p2p-onion:1 <адрес>.onion` вместо IP кандидати. `RTCPeerConnection` е с
   `iceTransportPolicy: "relay"` и без сървъри, така че не събира нищо и не прави STUN заявки.
3. Инициаторът се свързва към onion адреса на другия (порт 7777) и праща hello: HMAC с ключ от
   ефимерните ключове на двойката. Поток без правилно hello се затваря.
4. Отгоре вървят същите `hello` и Double Ratchet както винаги.

Ако само единият е в режима, свързването спира с ясно съобщение. Връщане към IP няма.

## Внимание

- **Nostr откриването** (Н2) отива директно към релетата и показва IP адреса ви: в този режим не го ползвайте.
- **Демо стаята** (кратък код) и Telegram виждат поканата, но в нея няма IP адрес.
- **Не е проверено** срещу истинската Tor мрежа от средата, в която е писано. Android билдът не е пускан
  на устройство.

Подробности: ADR-009, ADR-013, `docs/PROTOCOL.md` §9b.
